Fixing the trail so it reads as a walk, not a checklist

Four targeted fixes to the Path screen shipped in #143: match the info-popup close button, swap the square objective-icon nodes for round number badges in cycling theme colours, resolve the overflowing description at the card's foot, and reverse the scroll so level 1 starts at the ground and the walk climbs toward the sky.

Grounded in LevelPathPanelView.cs, InfoCardChrome.cs and the İlkbahar ThemeDefinition asset — no new colours, no new font asset assumed beyond what LevelPathButtonView already declares slots for.

Background is exactly today's flat per-zone band colour and scenery (Meadow shown here) — untouched. Only the trail on top of it changes: round nodes, the info-popup close button, and level 1 starting at the bottom instead of the top.

Close button fix 1

Swapped the flush square plate for the same floating circular plate + drop shadow + theme-ink × used across every other overlay.

Unity: stop hand-rolling BuildCloseButton in LevelPathPanelView; call InfoCardChrome.CreateCloseButton / PositionCloseButton against this card's own _cardRect instead, same as InfoPopupView already does.

Nodes fix 2

Circle plate, no objective glyph. Level number in Fredoka Bold, large and centred — the one thing every node needs to communicate at a glance while scrolling fast.

Colour cycles through the game's own 5-slot kind palette — the same set the block pieces and the Path pill's disc already use — so no new hue enters the game.

Unity: ConfigureCircle instead of ConfigureRounded for the plate; drop the objective Image build entirely; node.PlateImage.color = theme.GetFill((levelNumber - 1) % 5), current node still overrides to theme.Accent. Done-dot and reward badge keep their existing corner logic.

Description fix 3, kept

Split into a bold one-line objective label plus a smaller move/target line beneath, both centred and each independently truncated with an ellipsis rather than one long sentence that can overflow.

Unity: reuse ObjectiveDescriptionFormatter but request two shorter strings (or split the existing one on its first clause) instead of one Text; keep horizontalOverflow = Wrap as the true fallback if a locale still runs long.

Scroll direction fix 4

Level 1 anchored at the content's bottom; ScrollTo now measures depth from the bottom edge. Opening the card still centres on the player's current node — jumping "up" the walk instead of "down" it.

Unity: LevelPathTrailLayout.WaypointOf keeps the same sine sweep but content is anchored bottom (anchorMin/Max = (0.5, 0), pivot = (0.5, 0)) instead of top; ScrollTo's depth becomes content height − node depth.

Zone scenery unchanged

Confirmed after the first pass overcorrected this: the flat per-zone band colour and every scenery sprite (hills, river+bridge, trees for Meadow; mountains/pine/cloud for Winter; skyline/stadium/streetlamp for City; bakery/school/tree for Neighborhood) stay exactly as implemented — BuildScenery, BuildZoneBand, ZoneColour and LevelPathZones are untouched by this issue.

Unity: no changes here. Only ContentY's sense of direction flips with fix 4 (bottom-anchored content), which BuildScenery already computes from — the band boundaries and sprite offsets fall out of that unchanged.

Same background as today (flat per-zone band + scenery, untouched). Same card height, one more row of trail visible than board A. The per-level goal moves entirely onto the in-run HUD chip, which already shows it once a run starts.

Trade-off

Drops the only place a player can preview a level's goal before committing to it — they'd learn the objective only after tapping a node and reaching CoinSowerPickerView or the run itself.

Simpler to build and guaranteed never to overflow, since it's a short fixed phrase from the String Table rather than a formatted objective sentence.

Recommendation

Keep board A's two-line split unless the goal preview genuinely isn't valued — it's the smaller change from what exists, and it keeps information the current screen already promises the player.
